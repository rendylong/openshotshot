# 重档 PRO：整剧/系列生产（在六步之上叠加）

适用：整部剧 / 多集系列 / 商业交付。在中档六步（P0-P5）基础上，增加**序列状态机、情绪曲线、生成预算、take review** 四层。先完成需求澄清（`requirement-intake.md` §3 重档加问 4 项：系列规模 / 交付期限 / 生成预算 / 交付标准），再完整执行 `pipeline-standard.md`，本文只写增量。

## 增量一：系列圣经（Series Bible）

整剧开拍前先建立全局事实源（写入文本节点或「我的素材」，全剧引用）：

```text
【世界观】时代/法律/战力天花板 —— 任何集不得越界
【人物谱】每个角色的身份、动机、人物弧光起点、人际关系图谱（防无动机叛变）
【视觉宪法】全剧统一：色调基调、美术风格、构图母题、标志性视觉元素
【资产总表】CHR/SCN/PRP/AUD 编码台账（见 asset-first.md），跨集复用
```

规则：单集剧本只授权动「本集事实」，动到圣经层（人物死亡、关系反转）必须显式标注并让用户确认。

## 增量二：情绪曲线量化

在节拍表之上，给全片标 12 个节拍点的张力值（0-10），画成曲线给用户看：

```text
节拍1 开场钩子 ≥3.0 且必须即时冲突
中段至少一次刻意回落（4-5，给观众呼吸）
波峰 ≥9.0 全片不得少于 2 次
最高峰（通常在反击/反转）9.5+，位于 80-90% 进度处
结尾回落留钩子（4-5）
```

判定不过关就回 P1 改节拍表，不带病进分镜。曲线本身以文本节点存档（如 `EP01_情绪曲线_v1`），是后续每集对标的基准。

## 增量三：生成预算表

总时长 → 生成组的预算分配（Seedance 单段物理上限决定）：

```text
组数 = ceil(总秒数 ÷ 12~15)     例：180s → 13-15 组
每组自带从 00:00 起的完整时间轴，可整组独立投喂
高密度动作段：微步进切片 0.5-1.0s/片（运镜动词+力学动作+环境反馈）
严禁 1:1 机械压缩（把 3 分钟剧本塞 5 条 prompt）
```

每组对应脚本节点里的若干镜头；交付前给用户一张「组号 → 镜号 → 时长 → 状态」的预算表。

## 增量四：序列状态机与 take review

多组连续生成时，把每组当作一个「片段契约」管理：

### 片段契约（每镜/每组生成前明确）

```text
clip_id: U02-镜3
开场状态（必须 = 上一镜的 observed_end_state）
本镜单一动作 + 终点
引用：@已锁资产图（每维度唯一 owner）
保留节拍（本镜绝不能提前演的后续剧情 → 写进负面排除）
```

### take review 四裁决（每个生成结果必留记录）

| 裁决 | 条件 | 后续 |
|---|---|---|
| accept | 完成节拍、无连贯性破坏 | observed_end_state 写回契约链 |
| accept_with_deviation | 有偏差但不伤连贯 | 记录偏差，偏差进入后续镜的既成事实 |
| repair | 方向对但可修 | 单变量重roll（一次只改一个变量） |
| reject | 节拍失败/身份漂移 | **不作续接父本、不改正典**，按 retake 协议重来 |

记录以 `assets_add(kind=text)` 存「我的素材」（命名 `TAKE-U02-镜3-review`），内容：observed_start/end_state、completed/incomplete_beats、continuity_breaks、裁决。

### 正典纪律

- 「正典」= 已 accept 的镜头链 + 资产锁。后续所有镜的正典冲突以正典为准。
- 计划 ≠ 事实：绝不假装计划中的结局已发生；后续镜的开场状态永远用 observed，不用 planned。
- extension_depth ≤2：连续以生成结果为源的续接超过 2 代，强制回已锁资产图重锚。
- 场景边界 = 重锚点：换场必回资产参考图重开，把漂移截断在场景切换处。

## 增量五：交付 QC

成片交付前按 `qc-gates.md` 的 P0/P1/P2 全量过检，另加交付项：

```text
画面：分辨率/帧率/安全区/闪烁帧
色彩：统一色调基准、HDR-SDR 一致性
声音：对白 0dB > SFX -6dB > BGM -14~-18dB，激烈段 BGM 避让
连贯性：跨组衔接点逐对检查（上组 observed_end = 下组开场）
资产一致性：脸型/服装/道具 对标资产图册
命名：项目_集数_版本_画幅_语言_日期_状态
```

QC 校验表以文本素材存档，不入提示词正文。

## 重档执行节奏（和用户的分工）

```text
1. 系列大纲（圣经要点 + 分集规划 + 情绪曲线）→ 用户确认   ← 全剧唯一的「战略层」确认
2. 每集：单集大纲（立项卡 + 节拍表 + 实体清单）→ 用户确认
   →【大纲门禁】明确确认后才调 canvas_generate_script 建该集脚本节点（requirement-intake.md §6）
3. 每集：资产清单 → 确认 → 出图 → 确认
4. 每集：分镜表 → 确认 → 写入
5. 每组生成 → take review → 和解正典 → 下一组
（2-5 循环；用户说「跳过确认直接出整集」时静默过全套约束，但 P0 致命项仍阻断）
```
