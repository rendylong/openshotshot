# 需求澄清：开工前的必做环节

**原则：生成即扣费、返工即浪费。凡是「答错了就要全部重做」的信息，开工前必须向用户澄清；凡是纯专业执行层的信息，自己决定并汇报。** 需求未澄清前，禁止调用任何生成类工具（canvas_generate_script / canvas_generate_node / canvas_run_generation）。

## 1. 三类信息

| 类别 | 处理方式 |
|---|---|
| **必问项**（答错 = 返工） | 用选择题向用户收集，拿不到答复不开工 |
| **可默认项**（有合理默认值） | 给默认 + 说明，用户沉默即视为接受 |
| **禁问项**（专业执行层） | 自己定：选哪个词库词、用什么运镜、怎么分段——问这些是在把工作推回给用户 |

## 2. 澄清纪律

- **集中收集**：开工前一轮问完（一次 ≤4 个问题），不要挤牙膏式连环追问。
- **选择题优先**：每个问题给 2-4 个选项，第一项放推荐项并标注「（推荐）」；确实开放的问题才让用户打字。
- **先读画布再提问**：第零步 `canvas_get_state` 已经能看到的信息（已有参考图、已有脚本节点）不要重复问。
- **用户说「你定 / 随便」**：按缺省表取值，明确说一句「我按 XX 处理，随时可改」，并记进立项卡——不追着再问。
- **门禁即澄清**：中/重档的立项卡、资产清单、分镜表三处确认，本身就是需求澄清的延续；用户在确认时提出的修改 = 新需求，就地吸收。

## 3. 必问清单（按档位）

### 轻档（单镜头）必问 4 项

| # | 问题 | 选项示例 |
|---|---|---|
| 1 | 画幅？ | 16:9（推荐，横屏平台）/ 9:16（抖音/Reels）/ 2.35:1（电影感）/ 1:1 |
| 2 | 时长？ | 5s（推荐）/ 8-10s / 15s（2.5 可到 30s） |
| 3 | 用在哪？ | 即梦 / 火山方舟 API / ShotShot 生成节点 / 仅要提示词文本 |
| 4 | 有参考素材吗？ | 无，纯文字（推荐）/ 有角色图 / 有场景图 / 有模仿视频 |

模型版本可默认（Seedance 2.5），用户点名 Veo/Kling 时切换适配。

### 中档（单集）必问 6 项

| # | 问题 | 选项示例 |
|---|---|---|
| 1 | 故事来源？ | 一句话原创（推荐）/ 小说/文章改编 / 已有剧本 / 仿写爆款结构 |
| 2 | 题材类型？ | 都市情感 / 古风仙侠 / 悬疑 / 喜剧 / 带货 / 科幻（给推荐） |
| 3 | 单集时长？ | 60-90s（推荐短剧节奏）/ 2-3min / 30s 内 |
| 4 | 画幅？ | 9:16 竖屏（推荐短剧）/ 16:9 |
| 5 | 角色形象有素材吗？ | 无，全部 AI 生成（推荐）/ 有部分参考图 / 有必须保持的既定形象 |
| 6 | 台词与语言？ | 中文台词+中文提示词（推荐）/ 中文台词+英文提示词 / 无台词纯画面 |

平台与合规红线从用途追问（发抖音/红果 → 内容合规约束加严）。

### 重档（整剧）在中档基础上加问 4 项

| # | 问题 | 选项示例 |
|---|---|---|
| 1 | 系列规模？ | 3-5 集试水（推荐）/ 10 集以上 / 先做 1 集样片定标准 |
| 2 | 更新节奏/交付期限？ | 影响分批策略与 QC 严格度 |
| 3 | 生成预算约束？ | 无限制 / 有限次数（影响：更多先出首帧图确认，减少视频重roll） |
| 4 | 交付标准？ | 自用（标准 QC）/ 商业交付（全量 QC + take review 存档） |

## 4. 缺省表（用户不答时）

| 参数 | 缺省 | 适用条件 |
|---|---|---|
| 画幅 | 16:9 | 无平台信号 |
| 画幅 | 9:16 | 提到抖音/竖屏/短剧 |
| 模型 | Seedance 2.5 | 未点名其他模型 |
| 单段时长 | 5s（轻档） | 未指定 |
| 风格 | 按题材映射表 | 用户未给风格倾向 |
| 台词 | 无台词纯画面 | 用户未提对白 |
| 叙事视角 | 第三人称客观 | 未指定 |

## 5. 澄清完成的标准

- [ ] 必问项全部有答案（或用户明确说「你定」并已记录缺省）
- [ ] 缺省项已向用户口头列出，无人反对
- [ ] 画布已有素材与需求的关系已核对（复用 or 忽略）
- [ ] 产出立项卡（中/重档）或参数确认行（轻档）→ **这时才开始进流水线**

## 6. 剧本大纲确认（建节点前的最后一道门）

需求澄清完成后立刻创作大纲并请求确认。**用户明确同意之前，禁止调用 `canvas_generate_script` 创建脚本节点，也禁止进入资产出图与分镜写入。**

### 大纲模板（按档位）

**轻档 · 镜头大纲**（≤5 行，配 1-2 个备选创意方向更佳）

```text
主体：谁 + 外观关键词
动作：一个可见动作 + 终点
场景：地点 + 时段 + 光源
氛围/风格：方向词 2-3 个
参数：画幅 / 时长 / 运镜方向
```

**中档 · 单集大纲**（一屏内）

```text
前提：30 字（主角 + 欲望 + 阻碍 + 代价）
钩子：第 1 镜的黄金 3 秒方案（可给 2 个备选）
节拍表：每场一行（场景｜目标→阻碍→转折→不可逆新局面）
角色/场景清单：拟创建资产的名字列表
卡点：结尾停在哪个瞬间
```

**重档 · 系列大纲**：世界观要点 + 人物谱 + 视觉宪法 + 分集规划（每集一句话 + 承接关系）+ 首集单集大纲。

### 确认规则

- 展示大纲时附「可调整点」（备选钩子/两种结局方向/可换的角色设定），让用户容易提意见。
- **明确同意才算过门**：「可以」「确认」「就这样」；沉默、跑题、只回「嗯」都不是确认——追问一句「这版大纲可以吗？」。
- 用户提修改 → 当场改、再次确认；改动触及必问项（画幅/时长/题材/角色素材）→ 回第一步补问受影响参数。
- 用户显式说「不用确认，直接做」→ 记录这条授权，跳过等待，但仍要把最终大纲随产出展示。
- 确认后大纲即为契约：`canvas_generate_script` 的 instruction 用确认稿原文（中/重档含节拍表与实体清单）；后续任何偏离大纲的产出，要点出「这偏离了已确认大纲的 X」，重新征求同意后才保留。
